# Startup execution and legacy role dispatch

## Manager-led work

The selected harness, pane runtime and coordinator own admission and durable state. Load the complete manager role and `jp-startup-loop` from canonical sources. Authenticated identity determines authority; a pane label or self-report is not admission. Context projection binds source paths and hashes: changed instructions are not automatically admitted. Manager source handover is not yet implemented; preserve the active session and do not relabel it.

The manager saves input, captures actionable rows and schedules independent `jp-pipeline` or `jp-hotfix` runs. Each run owns implementation, independent review, verification, QA and the user-requested landing mode. The manager tracks cross-run dependencies and actual outcomes. Start a PA with `startup_ensure_pa` only when needed for questions. Do not require a persistent architect, developer and QA crew for new work. Helpers follow their assigned workflow and applicable review budget.

Use stable run identities and inspect actual receipts. A launch or report does not prove completion. Manager-led execution is covered by repository tests including an offline OMP coordinator fixture; live deployment remains unverified. Reconcile uncertain process launches or external effects before another attempt and continue unrelated work.

## Historical crew recovery

Previously admitted employees, teams, claims, grants and source receipts retain their original identities and authority. Do not overwrite a legacy binding, reinterpret a role receipt as a new manager run, or launch a replacement while its outcome is uncertain. Use the runtime README and the historical queue-records procedures for supported reconciliation and replacement. Tern replacement requires its saved pane and attested process to be proven absent as well as normal recovery evidence.

For migration, preserve the old root and external transcripts. Scoped queue migration adopts only eligible rows; separate-root legacy import archives its scoped or unscoped source and quarantines nonterminal rows. Snapshot hashes do not fence an active old process, establish whether work was dispatched, or transfer review authority. Old-owner handover and review-budget transfer are unsupported, so imported nonterminal work remains quarantined. Unrelated new work may proceed in the separate root without replaying old items.
