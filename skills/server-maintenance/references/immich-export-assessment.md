# Read-only Immich → Apple Photos export assessment

- Resolve the SSH target from its canonical server record and inspect Docker mounts, health, version endpoint, recent integrity logs, and database schema. Query only metadata needed for the audit; use PGOPTIONS=-c default_transaction_read_only=on with psql and exclude credentials.
- Inventory asset originals by owner, type, visibility, deletion/offline/external status, file path, original filename, checksum algorithm, capture dates, and EXIF file size. Include external-library mounts when present. Export only originals, never thumbnails or transcoded derivatives.
- Validate existence, size, and database checksum for every selected original. A recent scheduled integrity scan can miss uploads added afterward; compare its count with the current inventory. Use modest I/O concurrency.
- Compare Live Photo identifiers on images and videos, plus livePhotoVideoId links. Images carrying Apple content identifiers without matching motion videos are not complete Live Photos, even when every registered original checksum passes.
- Preserve database originalFileName mappings and collision-safe names. UUID storage filenames alone are insufficient for a clean human-readable export.
- Check embedded capture-date tags, not just database dateTimeOriginal: database dates may be fallback values that Apple Photos cannot recover from original bytes. Sample old/new photos and videos and inspect all small atypical groups (screenshots, PNG/WebP/TIFF). Restore verified dates only in staged copies; never edit live storage.
- Bound ExifTool scans. A whole HEIC library scan over network storage may exceed command timeouts, and an SSH timeout can leave its container process alive. Prefer explicit representative file lists, retain owned PIDs, and stop only the exact task-owned process if necessary. Treat incomplete scans as incomplete evidence.
- Inspect file signatures as well as extensions: a .png or .jpg name can disguise another format. Assess Apple's handling of uncommon formats with a small offline Photos-library import before bulk cutover.
- Do not claim a complete replacement from checksum success alone: consider missing motion companions, embedded dates, edits, albums, favorites, and exact Apple Photos import behavior. Distinguish verified source originals from a staged/exported and tested artifact.
- A local Photos.sqlite permission error is a macOS privacy boundary, not proof of a broken library. Do not bypass it or change iCloud settings during a source audit.

## Preparing staged import files
- Do not use ExifTool `-fast2` to determine that videos lack dates: it can skip QuickTime metadata after media data. Run a full metadata inspection before synthesizing missing capture dates.
- Correct file extensions that conflict with actual signatures before metadata writes. Preflight case-insensitive collisions and retain exact source names in a manifest; use an asset-ID suffix for collisions rather than overwriting an existing file.
- Treat Immich localDateTime's UTC-shaped representation as local wall-clock storage, not proof of UTC. When timeZone is missing, leave EXIF/XMP offsets absent; derive known offsets from capture-date-specific local/UTC values, not the machine's current timezone.
- Add dates only when no usable EXIF/XMP/IPTC/format-specific capture date exists. Keep unmodified versions of edited files and preserve source/prepared hashes. Label fallback timestamps as Immich-derived; filename/date disagreements require review, not silent correction.
- Separate MOV/MP4 date handling from image EXIF writes. Preserve valid existing video tags; for previously undated UTC-tagged sources, write UTC QuickTime integer dates and an explicitly offset-bearing creation string without double conversion.
- Verify each intended tag after writes, not just ExifTool exit status. A CSV write can report updated files without making every requested tag readable, and malformed existing XMP may prevent new XMP fields. Accept a verified supported capture field rather than claiming all requested fields landed.
- If adding EXIF to a staged PNG creates a new IFD/JUMBF warning, restore its exact unmodified source and use XMP-only date metadata rather than stripping unrelated metadata or repeatedly forcing the write. Flag those images for a real Photos date check.
- Native `sips` parsing validates local image readability, not Apple Photos import acceptance. Reconcile actual Photos counts and dates before destructive cutover; keep WebP originals if compatibility conversion is required.
