# Startup skill family Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the 12-dir `startup` skill family plus release wiring, implementing spec `a632eae` verbatim.

**Architecture:** One task per skill dir (12), each writing a single `SKILL.md` with `name` + `description` frontmatter only and Framework tail; role/command skills cross-reference via `skill://` names, never file paths. Final task wires README, CHANGELOG, VERSION, symlinks. Work in-place on `main`, one commit per task.

**Tech Stack:** Markdown skills; repo conventions (frontmatter, tail, ≤~500-word body or split refs); `gh` + Linear MCP referenced, not configured.

## Global Constraints

- Frontmatter keeps `name` + `description` ONLY — drop Cursor keys (`paths`, `disable-model-invocation`).
- Every SKILL.md ends with the Framework tail: `Before finishing, read \`../cleanup/SKILL.md\` (relative to this skill's repo directory; fallback \`$JP_SKILLS_REPO/skills/cleanup/SKILL.md\`) and follow it.` — except nothing here is `cleanup` itself.
- Supporting files only when the main reference would exceed ~500 words.
- State paths use the canonical home chain verbatim: `$JP_SKILLS_HOME`, else `$XDG_CONFIG_HOME/jp-skills`, else `~/.config/jp-skills`.
- NEVER persist queue/state under `tmp/` — `cleanup` Step 1 wipes it.
- No code, no tests in this repo (`NO_TEST_SUITE`); verification is read-through + grep gates.
- One commit per task, in-place on `main` (merging `main` into `main` is a no-op; no PR).
